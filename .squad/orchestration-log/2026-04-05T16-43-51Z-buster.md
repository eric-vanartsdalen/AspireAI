# Orchestration Log — Buster (QA / Tester) — 2026-04-05T16-43-51Z

## Mission
Define the minimum test gate for the next auth UX slice.

## Outcome
**Defined:** 5 acceptance gates (unauthenticated landing, mock login contract, full sign-in E2E flow, tenant propagation proof, provider pluggability) centered on multi-layer testing strategy before real OAuth attempted.

## Rationale
- Mock auth must have explicit, provable gates before swapping real providers
- Test layers (UI → Component → Integration → Service → Contract) validate different concerns
- Cross-service tenant isolation must be proven at Python service level (audit test)
- Provider pluggability must be testable via config-only changes (no code recompile)
- Playwright E2E confirms UX shapes match real OAuth later

## Test Strategy
- **Tier 1 (Critical):** `LandingPageTests.cs`, `MockAuthEndpointTests.cs`, `test_p0_auth_contract_audit.py`
- **Tier 2 (Functional):** `AuthFlowE2ETests.cs` (Playwright), `AuthProviderFactoryTests.cs`
- **Optional:** `SignInFormTests.cs` (Bunit component tests if logic complex)

## Acceptance Gates (In Order)
1. **Gate 1:** Unauthenticated landing page — `/` returns 200, sign-in buttons visible, chat/upload return 401 or redirect
2. **Gate 2:** Mock auth endpoint contract — `POST /auth/login` → 200 with `accessToken` + user object (userId, email, tenantId)
3. **Gate 3:** Cross-service tenant isolation — Python service receives tenant ID in header, persists in DB, unauthenticated requests return 401
4. **Gate 4:** E2E sign-in flow — Click provider button → enter email → redirect to dashboard → email visible → tenant dropdown functional
5. **Gate 5:** Provider pluggability — Config-only swap "mock" → "google" → factory loads provider without code recompile

## Contract Specs (Defined Before Implementation)
- **Auth endpoint:** `POST /auth/login` — email, provider in request → accessToken, user object (userId, email, tenantId) in response
- **Service pattern:** `AuthContextService` (scoped) mirrors `TenantContextService`; `IAuthProvider` interface abstraction
- **Tenant header:** Cross-service requests include `X-Tenant-Id` header; Python validates and filters

## Out of Scope (Post-Mock Phase)
- Real OAuth flows (Google/Microsoft callback)
- Encrypted token storage
- Refresh token lifecycle
- Session timeout / invalidation
- MFA
