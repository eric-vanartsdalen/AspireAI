# Orchestration Log — Jeff (.NET Dev) — 2026-04-05T16-43-51Z

## Mission
Shape the concrete Blazor UX slice for mock auth and unauthenticated entry.

## Outcome
**Recommended:** Landing page, Sign-In page with provider selection, Dashboard (protected), AuthenticationContext service, MockAuthProvider, AuthorizeView gating. DI-based provider registration for real auth later.

## Rationale
- Current app has no unauthenticated entry point; users land straight in chat
- TenantContextService model proves DI/scoped service pattern; auth mirrors it
- Blazor's built-in `AuthenticationStateProvider` + `<AuthorizeView>` is standard extensibility
- Mock providers now reduce real-provider scope creep later
- Provider buttons should visually resemble real OAuth (Microsoft blue, Google colors) for UX fidelity

## Design Deliverables
1. **AuthenticationContext** (scoped) — mirrors TenantContextService pattern
2. **IAuthProvider** interface + **MockAuthProvider** — pluggable backends
3. **Landing.razor** (`/`) — hero, sign-in CTA, public
4. **SignIn.razor** (`/signin`) — provider picker (mock, Microsoft stub, Google stub)
5. **Dashboard.razor** (`/dashboard`) — protected, shows Welcome message + tenant context
6. **UserMenu.razor** — avatar + name + logout, integrated in NavMenu

## Data Model
- **AuthenticatedUser:** UserId, DisplayName, Email, AvatarUrl, Provider, TenantId
- Phase 1: Mock users hardcoded; mock state lives in Blazor circuit memory
- Phase 6: Add `aspire_users` + `tenant_users` tables for persistent identity

## Acceptance Criteria
- Landing page shows at `/` for unauthenticated users
- Sign-in with provider button → mock login succeeds → redirect to Dashboard
- User name/avatar visible in top bar when authenticated
- Tenant auto-selects to user's default tenant on login
- Sign-out clears auth state, redirects to landing
- Playwright E2E tests cover login, tenant-auto-select, sign-out, unauthenticated redirect
- `dotnet build` succeeds; no auth-related warnings
